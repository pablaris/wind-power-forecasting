# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

IE University ML project: day-ahead (24 h) forecasting of hourly wind generation (MW) in the 9 Spanish
provinces with the highest wind output, from meteorological predictors.

`src/config.py` is the single source of truth for the study period, the provinces and the weather
variables, and every script imports it:
- **Period:** 2024-02-17 to 2026-06-30, inclusive.
- **Split:** the test set starts 2025-07-01.
- **Why it starts in 2024:** Open-Meteo only archives the day-ahead forecasts of the Previous Runs API from 2024 onwards.
- **Provinces and coordinates:** the `PROVINCES` dict holds one lat/lon point per province (its capital).

## Environment

- Use the conda env `machine_learning` (Python 3.12+), and activate it before running anything. On Windows, running the env's `python.exe` without activating the env makes numpy crash with `0xc06d007f`.
- `pip install -r requirements.txt`. It includes scikit-learn and xgboost; if xgboost is missing, `train_models.py` falls back to `HistGradientBoostingRegressor`.
- The ESIOS loader needs `ESIOS_TOKEN` in a `.env` file at the repo root. The file is gitignored and may be saved with a BOM, which is why the loader reads it with `utf-8-sig`.

There is no test suite, linter or build step.

## Data pipeline

`data/` is gitignored and is fully generated by these scripts. Run them in this order from the repo root:

```bash
python src/loaders/esios_client.py                            # ESIOS 10037 -> data/raw/esios/generacion_eolica.csv
python src/loaders/open_meteo_client.py --weather forecast    # -> data/raw/open_meteo/meteorology_forecast.csv
python src/loaders/open_meteo_client.py --weather reanalysis  # -> data/raw/open_meteo/meteorology_reanalysis.csv
python src/processing/merge_datasets.py --weather forecast    # -> data/processed/dataset_forecast.csv
python src/processing/merge_datasets.py --weather reanalysis  # -> data/processed/dataset_reanalysis.csv
python src/processing/check_dataset.py --weather forecast     # read-only coverage / missing-hours diagnosis
python src/models/train_models.py --weather forecast          # -> reports/{results,figures}/forecast/
python src/models/train_models.py --weather reanalysis        # -> reports/{results,figures}/reanalysis/
python src/visualization/make_report_figures.py               # both result folders -> reports/figures/report/
```

How the pipeline fits together:
- **Weather sources** (`--weather` flag):
  - `forecast` is the main source and has no leakage. It is the Open-Meteo Previous Runs API forecast issued about one day before each hour (`_previous_day1`).
  - `reanalysis` is the ERA5 archive, the weather that actually happened. It is used only as an upper bound ("perfect forecast").
- **Script structure:**
  - Scripts are top-level, and they resolve paths relative to their own file (`os.path.dirname(__file__)/../..`).
  - They import `config` by adding `src/` to `sys.path`.
- **Provinces and the merge:**
  - Both loaders take their province list from `config.PROVINCES`.
  - The ESIOS loader also saves a national ranking to `data/raw/esios/province_ranking.csv`.
  - Names must match ESIOS's `geo_name` exactly, accents included (e.g. `Cádiz`, `A Coruña`).
  - The merge is an inner join on `datetime` + `provincia`. It raises if the province sets differ between sources, and flags provinces with under 98% hourly coverage.
- **ESIOS download:**
  - The loader downloads month by month with retries.
  - It caches only complete months, in `data/raw/esios/monthly/`, so a rerun resumes from there.
  - It refuses to save the final CSV if any month fails.
- **Timestamps:** all are UTC. Parse them with `pd.to_datetime(..., utc=True)`.

## Modelling (`src/models/train_models.py`)

- **Models:**
  - persistence and climatology baselines
  - Ridge and Lasso
  - XGBoost
- **Validation:** `TimeSeriesSplit` CV (4 splits) for tuning, and 95% CIs from a block bootstrap over test days.
- **Progressive feature sets:** S1 History → S2 +Calendar → S3 +Weather → S4 +Physics. Province dummies are included in every set.
- **Lags:** generation lags are at least 24 h (`HORIZON`), so they are known at forecast time.
- **Flags:**
  - `--quick` uses small grids.
  - `--calendar {doy,month,season,none}` sets how time of year is encoded.
  - `--tag NAME` writes to `reports/*/NAME/` instead of `reports/*/<weather>/`. The `forecast/` and `reanalysis/` folders hold the team's tracked results, so use `--tag` for experiments.

## Dataset schema (`data/processed/dataset_<weather>.csv`)

- Keys: `datetime`, `provincia`
- Target: `generacion_mw`
- Features (`config.WEATHER_VARS`, wind speed is in m/s):
  - `wind_speed_100m`, `wind_direction_100m`
  - `wind_gusts_10m`, `temperature_2m`, `pressure_msl`

Column names, comments and some print output are a mix of Spanish and English. Keep the existing column names.

## Notebooks and EDA

Notebooks in `notebooks/` are meant to import their logic from `src/`. They read data with paths relative to
`notebooks/`, so run Jupyter from inside that folder or adjust the paths.

`src/eda/eda_esios.py` and the notebook read `data/processed/dataset_forecast.csv` (full 2024-2026 period).
`eda_esios.py` writes the 4 English-named EDA figures (`01_wind_power_curve.png` ... `04_temporal_cycles.png`)
to `reports/figures/`. The Spanish-named PNGs there are from the old 2021-2023 period and no script generates them.
